Observe
Read the current state. What does the system know right now?

Loop

The ReAct Pattern

Step through the agent's thought process live. Click tabs or use Prev/Next.

What is ReAct?
Reasoning + Acting interleaved in one loop.
💭Thought — What do I know? What next?
🔧Action — Call a specific tool
📋Args — Parameters for that tool
👁️Observation — Tool result injected back
🔁Repeat until goal achieved
💭 Thought 1
🔧 Action 1
👁️ Observe 1
💭 Thought 2
🔧 Action 2
👁️ Observe 2
🛑 HITL
ReAct Loop in Code
while not done and steps < MAX_STEPS: thought = llm.think(history, tools_available) # LLM reasons action, args = llm.decide_action(thought) # pick tool + params if action == "FINISH": done = True; break elif action == "APPROVE_RESET": wait_for_human_approval() # HITL gate else: obs = tools[action](**args) # call tool history.append(thought, action, obs) # add to context

Short-Term
🗒️
Context Window
Everything in the current conversation. The LLM sees this directly. Limited to token window (~128K tokens).
Like working memory — gone when the session ends.
Long-Term
🗄️
Vector DB / RAG
External storage with semantic search. Agent retrieves relevant chunks when needed. Survives across sessions.
Like Google Drive — search and retrieve on demand.
Episodic
📷
Checkpoints & Audit
Snapshots of agent state at each step. Enables recovery from failures, audit trails, and replay.
Like git history — you can roll back to any point.
Stop Conditions
Agents must know when to stop. Without stop conditions, they run forever (and cost money).
1
Goal achieved
Agent outputs FINISH signal
2
Max steps reached
Hard cap e.g. MAX_STEPS=8
3
Max retries
Tool failed MAX_RETRIES=2 times
4
HITL trigger
Risky action detected, pause for human
Retry & Fallback
When a tool fails, the agent doesn't crash — it retries intelligently.
try: result = vpn_reset(user="priya.n") except ToolError: retries += 1 if retries >= MAX_RETRIES: escalate_to_human() # fallback else: wait(2**retries) retry_tool()

Module 6

LangChain vs LangGraph

Same family, very different superpowers. Know when to use which.

🦜 LangChain
Linear Chains
Input → Step 1 → Step 2 → Output. Like an assembly line. Great for RAG pipelines, simple Q&A, summarization.
→
🕸️ LangGraph
Directed State Graphs
Nodes connected by conditional edges. Supports loops, branches, parallel paths. Built for complex agents that reason and retry.
Feature🦜 LangChain🕸️ LangGraph
Execution modelLinear chain / DAGDirected state graph (cycles OK)
State managementStateless per callPersistent typed state object
Loops / cycles❌ Not native✅ First-class citizen
CheckpointingManualBuilt-in (SQLite / Redis)
Human-in-the-loopRequires custom codeNative interrupt / resume
Best forRAG, Q&A, pipelinesComplex agents, HITL, multi-step
Rule of thumb: Start with LangChain for pipelines (input → output). Upgrade to LangGraph when your agent needs to loop, branch on conditions, checkpoint mid-run, or pause for human approval. The VPN lab uses LangGraph's state machine design with OpenAI function calling.
